# 荒原小隊 · Godot 開發路線圖

呢份文件係俾人同 Claude Code 一齊睇嘅。每個階段都有目標、內容、合格標準同一段可以直接複製嘅 prompt。

## 已定嘅決定

- 平台：手機，**直向**畫面（1080x1920）
- 引擎：最新穩定版 **Godot 4**，Mobile renderer
- 美術：3D 低多邊形**分件角色** + 手繪質感貼圖 + 固定斜角**正交**鏡頭
- 世界觀：原創，受 Kenshi 啟發，但唔用任何 Kenshi 名稱、劇情或素材
- 規則參考：repo 根目錄嘅 `index.html` 係網頁原型，入面嘅遊戲規則（傷勢、技能、經濟、勢力等）係設計依據
- Godot 專案放喺 `godot/`，唔好郁 `index.html`（GitHub Pages 仲用緊）
- 素材只用自己整嘅或者 CC0 授權

## 未定、要喺對應階段前決定

| 決定 | 最遲幾時 |
|---|---|
| 目標平台：先Android，和手機網頁版 | 階段 1 開始前 |
| 世界觀：戰國廢村 | 階段 3 開始前（影響地名、勢力名、物品名） |
| 收費模式：買斷、免費試玩＋解鎖完整版 | 階段 7 開始前 |

## 架構原則（所有階段都適用）

1. **模擬同畫面分開**：遊戲規則（傷勢、技能、AI、經濟）寫成純 GDScript 類別，唔依賴場景節點；畫面只係讀取狀態去顯示。咁先寫得到自動測試，之後做遠距離 NPC 簡化模擬都容易
2. **資料驅動**：物品、武器、盔甲、義肢、角色、勢力用 Resource 定義，唔寫死喺程式
3. **一開始就有存檔**：每加一個系統，都要同步支援存檔同讀檔
4. **自動測試**：用 GUT 或者 gdUnit4 為規則寫測試；每個 PR 都要測試全過
5. **每個階段一個 branch、一個 PR**，合併前要喺真手機試過

## 階段 0：灰模驗證（已驗證）

驗證分件角色可以換甲、換刀、斷手、裝義肢、揹人、瞓床。

## 階段 1：核心操作垂直切片

**目標**：喺真手機直向畫面，玩到同網頁原型一樣嘅操作手感。

**內容**
- 喺真手機測試嘅流程：設定匯出（Android 或 iOS），寫低步驟
- 直向鏡頭：單指拖動、兩指縮放、雙擊頭像跟隨
- 選取：點選、長按再拖框選、「框選」模式掣、全選
- 指令：點地面移動（陣形）、點敵人攻擊、暫停時指令排隊（虛線顯示）
- 戰術暫停、¼ 慢鏡、遇敵自動暫停
- 真正尋路：NavigationRegion3D 加角色互相避讓
- 4 個隊友、1 組敵人、基本近戰同遠程
- 五部位傷勢（簡化版，先唔做斷肢）
- 直向介面：頂部狀態、底部頭像列（可左右滑，最多 8 人）、右下指令掣
- 存檔同讀檔

**合格標準**
- 喺中階手機穩定 60fps（10 對 10 戰鬥）
- 角色唔會穿過障礙物，唔會卡死
- 長按框選同拖動鏡頭唔會撳錯
- 單手直向玩到一場戰鬥

**Prompt**
```
請讀 docs/ROADMAP.md 同 index.html，然後做「階段 1：核心操作垂直切片」。
階段 0 嘅分件角色已經喺 godot/ 入面，請沿用。
先俾我一個計劃（檔案結構、模擬同畫面點分開、介面排位），等我確認先開始寫。
寫完要：跑全部自動測試、用 Godot headless 檢查冇錯誤、喺新 branch commit 同開 PR、
喺 godot/README.md 更新點樣喺手機測試。
```

## 階段 2：搬入核心規則

**目標**：將網頁原型嘅戰鬥同生存規則完整搬去 Godot，有自動測試保護。

**內容**
- 五個用嚟練技能（耐打、攻擊、閃避、急救、力量），等級加進度條
- 三層傷勢：殘廢、斷肢、陣亡；流血；倒地按血量回復先醒
- 義肢（用階段 0 嘅分件系統）
- 行為規則 AI：低血就逃、救人醫人、見敵就打；連按兩次指令強制執行；複製規則去全隊
- 手動包紮（自己、隊友、敵人止血）、有敵人時減速同會被打斷、包紮期間唔還手
- 揹人、放低、跟隨、一齊行時等最慢嗰個
- 野狗（攻擊所有人）、流寇（補刀）
- 硬派模式開關
- 角色卡（直向用底部抽屜）：人形傷勢圖、技能、裝備

**合格標準**
- 每條規則都有對應自動測試，數值同網頁原型一致
- 一場戰鬥由頭打到尾，存檔再讀檔，狀態完全一樣

**Prompt**
```
請讀 docs/ROADMAP.md 同 index.html，然後做「階段 2：搬入核心規則」。
index.html 入面嘅數值同公式係標準答案，請逐條搬過去，唔好自己改平衡。
如果發現原型有 bug 或者規則矛盾，列出嚟問我，唔好自己決定。
先俾我計劃，等我確認先開始。每個規則都要有自動測試。完成後開 PR。
```

## 階段 3：世界同經濟

**開始前要決定世界觀**（沙漠廢土定戰國廢村），咁地名、勢力名、物品名先一次過定好。

**目標**：有一條完整嘅「賺錢、變強、再出發」循環。

**內容**
- 物品、背包、負重（練力量）、裝備、地上物品堆（5 分鐘消失）、交俾隊友
- 執屍、商人（買賣）、礦場採礦、懸賞（生擒交俾守衛）
- 醫療包、旅館租床、飢餓同食物
- 勢力關係值：城鎮守衛、商人、流寇、野獸、拾荒者、遊商隊
- 酒吧招募（有專長嘅角色）、移除陣亡隊友
- 一張完整嘅中型地圖：城鎮、礦場、獸竇、敵營、路線
- 商店、背包等長列表用直向友好嘅介面

**合格標準**
- 新玩家可以喺 30 分鐘內完成：練功、賺錢、買裝備、打倒頭目、交懸賞
- 拾荒者同遊商隊喺地圖上正常運作，唔會卡住

**Prompt**
```
請讀 docs/ROADMAP.md 同 index.html，然後做「階段 3：世界同經濟」。
世界觀已經決定用：【填你嘅決定】。請將原型入面嘅名稱（綠洲鎮、流寇等）改成符合呢個世界觀嘅原創名稱，
先列一張名稱對照表俾我確認。然後俾我計劃，等我確認先開始。完成後開 PR。
```

## 階段 4：第一輪正式美術

**目標**：一個區域達到可以做宣傳截圖嘅質素。

**內容**
- 正式分件角色模型（2 至 3 個體型）、手繪貼圖、共用骨架動畫（待機、行、跑、攻擊、受傷、倒地、被揹、瞓、爬）
- 一個地形主題嘅地面、建築、植物、道具
- 打擊、流血、升級等特效；基本音效
- 介面正式美術（參考 `docs/reference/` 嘅氣氛圖）
- 角色喺手機直向實際大細下，敵我、傷勢、裝備仍然一眼睇得出

**Prompt**
```
請讀 docs/ROADMAP.md，然後做「階段 4：第一輪正式美術」嘅技術部分：
建立美術匯入流程（命名規則、資料夾、匯入設定）、共用骨架同動畫狀態機、材質同描邊 shader 嘅最終版本、
特效同音效系統。模型同貼圖由我提供，請先用佔位素材，並寫低每件素材嘅規格（多邊形上限、貼圖大細、骨架點名稱）。
先俾我計劃，等我確認先開始。完成後開 PR。
```

## 階段 5：大世界

**內容**
- 多個區域，區域之間無縫或者轉場
- 遠距離角色用簡化模擬（只計數據唔計畫面）
- 巡邏隊同世界事件
- 全隊倒地會被俘虜：監倉、逃獄、救人
- 更多勢力同勢力之間嘅關係

**合格標準**：100 個以上角色同時存在，中階手機仍然 60fps；長時間遊玩冇記憶體洩漏。

## 用 Claude Code 嘅習慣

- **一次一個階段**，太大嘅階段可以再拆細，例如「階段 2 只做技能同傷勢」
- **永遠叫佢先出計劃**，確認方向先寫
- **每次都開 branch 同 PR**，唔好直接改 main
- **喺真手機試過先合併**
- 遇到唔啱，直接講現象：「長按框選時，鏡頭會跟住郁」比「操作唔順」有用好多
- 有新決定，請佢更新呢份文件
